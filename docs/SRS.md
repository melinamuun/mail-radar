## 1. 개요

### 1.1 목적
매주 월·금 06:00(KST)에 최근 수신 메일을 자동 수집·분류해 트리아지 대시보드를 만들고 본인 이메일로 발송한다. 수신함의 약 80%를 차지하는 뉴스레터·광고 노이즈에 묻힌 "처리할 메일"을 정해진 시각에 위로 끌어올려 빠르게 트리아지하는 것이 목표다.

### 1.2 범위
- 포함: 스케줄 트리거, 시간 창 계산, Gmail 수신 조회, 레코드화·분류·정렬, 인터랙티브 HTML 대시보드(첨부)·정적 요약(본문) 생성, 본인 메일 발송.
- 제외: 메일 회신·라벨링·삭제 등 쓰기 작업, 실시간 알림, 다중 사용자.

### 1.3 정의
- **수집 시간 창**: 한 번의 실행이 다루는 `[start, end)` 시각 구간. 모두 KST 기준.
- **트리아지**: 확인필요 메일을 상단에 끌어올린 우선순위 정렬 검토.
- **확인필요(action)**: 사람이 답장·조치해야 하는 메일. 유일하게 `high`.

## 2. 기능 요구사항 (FR)

각 FR은 인수조건(AC)을 가진다. 정상·예외 경계의 Given-When-Then은 `합류명세서.md`에서 상세화한다.

### FR-1 스케줄 트리거
- 월·금 06:00(KST)에 워크플로를 1회 기동한다.
- **AC**: cron `0 6 * * 1,5`, 타임존 `Asia/Seoul`. 그 외 요일·시각엔 자동 기동하지 않는다.

### FR-2 수집 시간 창 계산
- 실행 요일에 따라 `[start, end)`를 epoch로 정확히 계산한다.
  - 월요일: 지난 금 06:00 → 월 06:00 (주말분)
  - 금요일: 월 06:00 → 금 06:00 (주중분)
  - 수동 실행: 최근 48시간
- **AC**: 상대값(`newer_than`) 사용 금지. 06:00 경계를 epoch(초)로 계산한다. 월·금 두 창은 빈틈·중복이 없어야 한다(NFR-6과 연결).

### FR-3 Gmail 수신 조회
- `in:inbox` + `receivedAfter`/`receivedBefore`(시간 창)로 메시지를 조회한다.
- **AC**: `simple=false`, 전체 페이지 수집(`returnAll`). `labelIds`에 `INBOX`가 없고 `SENT`만 있는 항목은 제외(수신만).

### FR-4 레코드화·정규화
- 각 메시지를 표준 레코드로 변환한다: `{ from, email, subj, snip, date(ISO UTC), cat, prio, unread }`.
- **AC**:
  - `from`: 발신자 표시명(따옴표·잡문자 정리). 표시명 없으면 주소로 대체.
  - `subj`: 제어문자 제거, 트림.
  - `snip`: snippet 160자 이내 절단.
  - `date`: `internalDate` 우선, 없으면 Date 헤더 → ISO.
  - `unread`: `labelIds`에 `UNREAD` 포함 여부.

### FR-5 분류·우선순위
- 레코드를 6분류(`action`/`account`/`study`/`outlier`/`security`/`news`) 중 하나로 판정하고 `prio`(`high`/`mid`/`low`)를 부여한다.
- **AC**:
  - 노이즈 패턴(뉴스레터/보안/공지/학습/기회)에 걸리면 해당 분류로.
  - 어떤 노이즈 패턴에도 안 걸리면 `action`/`high`로 격상한다(안전한 방향의 오탐 허용).
  - `action`만 `high`를 가질 수 있다.
- 분류 기준(rubric)은 §6 표를 따른다.

### FR-6 정렬
- 확인필요를 최상단으로 끌어올린다.
- **AC**: 1순위 `action` 여부, 2순위 `prio`(high<mid<low), 3순위 `date` 내림차순.

### FR-7 인터랙티브 대시보드 생성 (첨부)
- 자기완결형 HTML 1파일을 만든다(통계·카테고리 탭·검색·우선순위 색).
- **AC**: 외부 파일·네트워크 의존 0(템플릿 내장). 파일명 `inbox-YYYYMMDD.html`. 시간은 KST 자동 변환 표기.

### FR-8 정적 요약 본문 생성 (이메일 본문)
- JS 없는 정적 HTML 요약표를 만든다(확인필요 / 계정·학습·기타).
- **AC**: 스크립트 없이 어떤 메일앱에서도 표시 가능. 전체·확인필요·안읽음·뉴스레터 건수를 헤더에 표기.

### FR-9 발송
- `selfEmail` 주소로 제목·본문(정적표)·첨부(대시보드)를 발송한다.
- **AC**: 본문은 HTML로 렌더. 제목 형식 `[수신 메일] {날짜(요일)} · 전체 N / 확인필요 M`. 첨부는 `text/html`.

## 3. 비기능 요구사항 (NFR)

### NFR-1 시간 정확성
- 모든 시각 계산은 KST 06:00 경계를 epoch로 환산해 초 단위로 정확히 자른다. 상대 표현 금지.

### NFR-2 무인 운영
- 호스트는 06:00에 상시 가동되어야 한다. 권장 호스팅은 항상 켜진 Synology NAS(Docker).

### NFR-3 외부 의존 최소화
- HTML 템플릿은 워크플로에 base64로 내장한다. 런타임에 외부 파일·LLM 호출 0(현 버전).

### NFR-4 호환성
- 이메일 본문은 정적 HTML만 사용한다. 인터랙션은 첨부 대시보드에만 둔다.

### NFR-5 보안·프라이버시
- 발송 대상은 본인(`selfEmail`) 1인. 메일 본문은 snippet 요약까지만 노출(원문 덤프 금지).
- 자격증명은 n8n Credential에만 보관한다(코드·문서에 평문 금지).
- **AC-NFR5.1 (XSS 방어)**: 대시보드·정적 요약표에 주입되는 모든 외부 메일 문자열(`from`/`email`/`subj`/`snip`)은 HTML 이스케이프(`& < > " '`)를 거친다. 미가공 문자열의 `innerHTML`/HTML 문자열 주입 금지. (L-5 승격)

### NFR-6 멱등성·무중복
- 월·금 두 실행의 시간 창은 맞물려 빈틈·중복이 없어야 한다(금06:00이 양쪽 경계, 한쪽은 포함·한쪽은 배타).

### NFR-7 테스트 가능성 (회귀)
- 분류 로직(`classify()`)은 n8n 외부에서 격리 실행 가능한 **회귀 테스트 하니스**를 가진다.
- **AC-NFR7.1**: 픽스처 메일 데이터셋에 대해 기대 분류(`cat`/`prio`)를 assert하는 테스트가 존재하고, 규칙 변경 시 수동 Execute 없이 회귀를 검출한다.
- **AC-NFR7.2**: 하니스는 별도 사본이 아니라 **워크플로 JSON에서 실제 `classify()`를 추출**해 테스트한다(로직 드리프트 방지).

### NFR-8 운영 안정성 (실패 가시성)
- 수집·발송 실패가 **침묵하지 않아야** 한다(현재 SPOF: 발송 실패 시 에러로 종료될 뿐 알림 없음 — L-2).
- **AC-NFR8.1**: 발송/조회 실패 시 별도 채널(n8n Error Trigger → 본인 메일)로 실패가 통지된다. 산출물 `n8n/error-handler-workflow.json` 제공 — 배포 시 본체의 Error Workflow로 연결(배포가이드 §4).

## 4. 데이터 모델 (ERD 대체)

DB가 없는 무상태 파이프라인이므로 테이블 대신 두 객체 스키마로 데이터 모델을 고정한다.

### 4.1 Window (Compute Window 출력)
```
{ q, startISO, endISO, end(epoch s), runType, rangeLabel, runDateLabel, selfEmail }
```

### 4.2 MailRecord (Build Dashboard 내부)
| 필드 | 타입 | 규칙 |
|---|---|---|
| from | string | 발신자 표시명(정리) |
| email | string | 실제 발신 주소 |
| subj | string | 제목(제어문자 제거) |
| snip | string | snippet 요약(≤160자) |
| date | string | ISO 8601 UTC |
| cat | enum | action/account/study/outlier/security/news |
| prio | enum | high/mid/low |
| unread | boolean | UNREAD 라벨 여부 |

## 6. 분류 기준 (rubric)

| cat | 의미 | 기본 prio |
|---|---|---|
| action | 답장·조치 필요(개인 메일, CI 실패, 마감) — 유일하게 high | high |
| account | 계정·약관·정책 공지 | mid/low |
| study | 강의·녹화본·연구 알림 | mid/low |
| outlier | 기회·제안·채용(반복 多, (×N) 압축) | low |
| security | 로그인·접근 알림(대개 본인 유발) | low |
| news | 뉴스레터·광고·다이제스트(노이즈 버킷) | low |

- 핵심 원칙: 노이즈는 패턴으로 잡힌다 → "노이즈가 아닌 것"은 확인필요에 가깝다. 패턴 미적중 시 `action`/`high` 격상.
- 개인화: 본인 프로젝트 연계 메일(내 레포 CI 실패, 지원 단체 회신 등)은 일반 패턴보다 우선해 `action`.

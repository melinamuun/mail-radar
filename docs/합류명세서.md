# 합류 지점 명세서 — 수신 메일 대시보드 자동화

> 설계와 구현을 한 기준점으로 묶는 단일 진실 공급원의 실행 명세.
> 여기의 Given-When-Then(GWT)은 그대로 **수동 테스트 시나리오 / 회귀 체크리스트**로 이식된다.
> 정상 경로뿐 아니라 **예외·실패·롤백**을 반드시 적는다.
> 관련: `SRS.md`(FR/NFR 번호), `아키텍처.md`(노드 매핑)

| 항목 | 값 |
|---|---|
| 문서 버전 | v1.0 |
| 작성일 | 2026-06-29 |

표기: 각 시나리오에 `[검증]` = 수동 테스트에서 눈으로 확인할 항목.

---

## 1. 시간 창 계산 (FR-2)

### AC-2.1 월요일 실행 — 주말분
- **Given** 실행 시각이 월요일 06:00(KST)이고
- **When** Compute Window가 동작하면
- **Then** start=지난 금 06:00, end=이번 월 06:00, runType="주말분"
- `[검증]` 수동 실행 후 출력 JSON의 `rangeLabel`이 금→월 구간인가.

### AC-2.2 금요일 실행 — 주중분
- **Given** 금요일 06:00(KST)
- **When** 동작하면
- **Then** start=이번 월 06:00, end=이번 금 06:00, runType="주중분"

### AC-2.3 경계 무중복 (NFR-6)
- **Given** 금06:00에 도착한 메일 1건
- **When** 월·금 두 실행이 모두 돌면
- **Then** 그 메일은 **정확히 한 번만** 어느 한쪽 창에 포함된다(`receivedAfter`/`Before`의 포함·배타 경계).
- `[검증]` 금06:00 직전/직후 메일이 양쪽에 중복 표시되지 않는가.

### AC-2.4 수동 실행
- **Given** 월·금이 아닌 요일에 수동 Execute
- **When** 동작하면
- **Then** 최근 48시간 창, runType="수동 실행"으로 폴백한다.

## 2. 수신 조회·필터 (FR-3)

### AC-3.1 수신만 포함
- **Given** `labelIds`에 `SENT`만 있고 `INBOX`가 없는 항목
- **When** Build Dashboard가 처리하면
- **Then** 해당 항목은 제외된다.
- `[검증]` 결과에 본인이 보낸 메일이 섞이지 않는가.

### AC-3.2 0건 (예외)
- **Given** 시간 창에 수신 메일이 0건
- **When** 파이프라인이 끝까지 돌면
- **Then** 빈 표 + "조건에 맞는 메일 없음"이 본문·대시보드에 표시되고 발송은 **정상 진행**된다(실패 아님).
- `[검증]` 0건 상황(예: 짧은 수동 창)에서도 메일이 오고, 표가 비어 있다고 안내되는가.

## 3. 분류·격상 (FR-5) — 핵심 위험 구간

### AC-5.1 노이즈 패턴 적중
- **Given** 발신 주소/제목에 `newsletter`,`no-reply`,`unsubscribe` 등 뉴스 패턴이 있는 메일
- **When** classify()가 판정하면
- **Then** cat=news, prio=low.

### AC-5.2 미적중 → 격상 (안전한 오탐)
- **Given** 어떤 노이즈 패턴(보안/학습/기회/계정/뉴스)에도 안 걸리는 메일
- **When** 판정하면
- **Then** cat=action, prio=high로 격상된다.
- 근거: 놓친 확인필요(거짓음성)가 불필요한 격상(거짓양성)보다 비용이 크다.
- `[검증]` 개인이 보낸 일반 메일이 news로 새지 않고 action에 올라오는가.

### AC-5.3 개인화 우선 (알려진 한계)
- **Given** 본인 프로젝트 연계 메일(내 레포 CI 실패, 지원 단체 회신)
- **When** 판정하면
- **Then** 일반 패턴보다 우선해 action으로 분류되어야 한다.
- 현재 한계: 키워드 규칙만으로는 완전 보장 못 함. 오분류 발견 시 → **SRS §6 rubric에 패턴 추가 후 버전업**(코드 직접 수정 아님). #2 Gemini 노드가 이 한계를 해소.

## 4. 정렬 (FR-6)

### AC-6.1 확인필요 최상단
- **Given** action·news·study가 섞인 결과
- **When** 정렬하면
- **Then** 모든 action이 맨 위, 그 안에서 prio(high→low), 같으면 date 내림차순.

## 5. 산출물 생성 (FR-7·8)

### AC-7.1 자기완결 대시보드
- **Given** 생성된 첨부 HTML을 네트워크 없는 환경에서 열면
- **Then** 통계·탭·검색·우선순위 색이 모두 동작한다(외부 의존 0).
- `[검증]` Wi-Fi 끄고 첨부를 브라우저로 열어 검색이 되는가.

### AC-8.1 본문 정적 렌더 (예외 대비)
- **Given** 정적 요약표를 포함한 발송 메일
- **When** 메일앱이 표시하면
- **Then** 표가 정상 렌더된다. raw HTML 코드가 그대로 보이면 → 발송 노드 메시지 타입을 **HTML**로 지정(SRS §5 제약).
- `[검증]` 받은 본문이 표로 보이는가, 코드 텍스트로 보이는가.

## 6. 발송 (FR-9)

### AC-9.1 정상 발송
- **Given** Build Dashboard 출력(summary + binary)
- **When** Gmail 발송 노드가 동작하면
- **Then** selfEmail로 제목/본문/첨부가 도착한다.

### AC-9.2 발송 실패 (예외 — 현재 미구현, 백로그 #5)
- **Given** Gmail API 오류(인증 만료·쿼터)
- **When** 발송이 실패하면
- **Then** (목표) 실패가 별도 채널로 알림되어야 한다. **현재 동작**: n8n 실행이 에러로 종료될 뿐 별도 알림 없음.
- 처리 방침: 운영 안정화(#5)에서 실패 알림·재시도 추가. 그 전까지는 n8n 실행 로그로 수동 확인.
